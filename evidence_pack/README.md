## 三、编号规则

**格式 `E<幕>-<序号>`**，文件名 `<编号>_<原文件名>`：

| 前缀 | 含义 | 条目 |
|---|---|---|
| `E1` | 第〇幕 能不能做（前基座） | 7 |
| `E2` | 第一幕 人群主效应 + 第四幕激素轴（含 PhenoAge 效度、死亡、稳健性） | 33 |
| `E3` | 第一幕副线 PFAS 修饰（三个突破口 + 混合暴露） | 15 |
| `E4` | 第二/三/四幕 单细胞 + 外部队列 + 结构分析 | 21 |
| `E5` | 后基座 可信度（L1–L4 + 四问 + 台账） | 39 |
| `E6` | 图（PNG 与 PDF 共用编号） | 22 |
| `E7` | 代码 | 18 |
| `E8` | 报告正文 | 2 |

**三条约定**：

1. **编号顺序 = 论证顺序**，不是文件名顺序。找一个数字，先想它在哪一幕。
2. **一份文件可被多个编号引用**（例如 `liver_decomp.csv` 同时是 `E2-23` 与 `E3-08`）。索引的 `origin` 列能看出重复。
3. **不复制可重建的二进制**：`results/*.rds`（含 95 MB 的 `cf_results.rds`）、`results/geo_pseudobulk_counts.csv.gz`（50 MB）、`verification/cluster_objects.rds`。它们由 `07_code/` 里的脚本重建。

## 四、`INDEX.csv` 字段

| 字段 | 说明 |
|---|---|
| `id` | 证据编号，如 `E5-30` |
| `act` | 幕（1–8），对应文件夹 |
| `section` | 报告章节（`§3.14` / `C.7` / `图 12`） |
| `claim` | **这份文件支撑哪一句话**（不是文件内容摘要） |
| `file` | 本包内相对路径 |
| `origin` | 原位路径（`results/…` / `verification/…`） |
| `source_script` | 生成该文件的脚本（自动 grep 反查；空白表示历史/中间产物） |
| `key_number` | 文件里的关键数字 |

## 五、三种用法

**① 按幕读**（写论文时）
```bash
# 只看第一幕副线（PFAS 修饰）
python -c "import csv,io;[print(r['id'],r['claim'],r['file']) for r in csv.DictReader(io.open('INDEX.csv',encoding='utf-8-sig')) if r['act']=='3']"
```

**② 按数字查**（审稿人挑刺时）
正文任取一个数字 → 在 `05_verification/E5-38_verification_ledger.csv`（256 条记录）里按 `value` 或 `metric` 搜 → 得到 `source` 列的文件名 → 到本包对应编号的 CSV 里定位原始行。

**③ 按质疑查**（答辩时）
`00_story/storyline.md` 的第六节是"审稿人可能问什么 → 去哪张表"的对照表，覆盖 10 类常见质疑。

## 七、这份包**不包含**什么
